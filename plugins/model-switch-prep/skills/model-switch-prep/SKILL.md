# Model Switch Prep — 확인 → 압축 → 모델 변경

새 모델 버전이 나왔을 때 진행 중인 세션을 그 모델로 넘기는 절차다. 순서는 항상 **① 컨텍스트 사용량 확인 → ② 압축 → ③ 모델 변경 → ④ 검증**이다.

이 순서를 지키는 이유:
- 모델을 바꾸면 기존 대화 전체를 새 모델이 처음부터 다시 읽는다. Claude Code는 모델 변경 시 프롬프트 캐시가 무효화되므로, 긴 기록을 그대로 넘기면 첫 턴 비용과 지연이 커진다. 압축을 먼저 하면 새 모델이 읽을 분량이 줄어든다.
- 새 모델의 컨텍스트 창이 현재 모델보다 작을 수 있다. 현재 사용량이 새 모델 한도를 넘으면 압축 없이는 전환이 실패하거나 앞부분이 잘린다.
- 압축 요약을 이전 모델이 만들면, 지금까지의 작업 맥락을 가장 잘 아는 쪽이 요약하게 된다.

## 중요한 제약: 슬래시 명령은 사용자가 입력한다

`/context`, `/status`, `/compact`, `/model` 같은 내장 슬래시 명령은 에이전트가 스스로 실행할 수 없다. 이 스킬에서 에이전트의 역할은 (1) 무엇을 입력할지 정확히 알려주고, (2) 압축 때 보존할 내용을 담은 지시문을 만들어 주고, (3) 필요하면 인계 메모 파일을 남기는 것이다. 명령을 "실행했다"고 말하지 말고, 사용자가 입력할 명령을 그대로 복사할 수 있는 형태로 제시한다.

## 1단계: 환경 판별

먼저 지금 어느 도구 안에 있는지 판단한다. 시스템 프롬프트, 사용 가능한 도구, 사용자가 언급한 이름으로 알 수 있다. 판단이 안 되면 두 가지 명령을 모두 보여준다.

| 단계 | Claude Code | Codex CLI |
|---|---|---|
| 사용량 확인 | `/context` | `/status` |
| 압축 | `/compact <보존 지시>` | `/compact` |
| 모델 변경 | `/model <모델명>` (생략 시 선택창) | `/model` (선택창에서 모델·추론 강도 선택) |
| 변경 확인 | `/status` 또는 `/context` | `/status` |

명령 이름은 버전마다 바뀔 수 있다. 사용자가 명령이 없다고 하면 `/` 를 입력해 목록을 확인하라고 안내한다.

## 2단계: 컨텍스트 사용량 확인

사용자가 이미 사용량(%, 토큰 수)을 붙여 넣었다면 이 단계는 건너뛴다. 아니면 위 표의 확인 명령을 입력하고 결과를 붙여 달라고 요청한다. 한 줄이면 충분하다.

사용자가 바꾸려는 모델 이름도 함께 확인한다. 이미 말했다면 묻지 않는다. 모르면 `/model` 선택창에서 고르면 된다고 안내하고 진행한다.

결과를 받으면 다음 기준으로 판단한다.

| 현재 사용량 | 판단 |
|---|---|
| 새 모델 컨텍스트 한도에 근접하거나 초과 | 압축 필수. 압축 후 다시 확인해서 한도 아래인지 본 뒤 전환 |
| 약 50% 이상 | 압축 권장 (기본 경로) |
| 약 20~50% | 압축 선택. 작업 맥락이 중요하면 압축, 가벼운 세션이면 바로 전환해도 됨 |
| 약 20% 미만 | 압축 생략 가능. 바로 3단계 건너뛰고 모델 변경 |

새 모델의 컨텍스트 창 크기를 모르면 확인되지 않았다고 말하고, 보수적으로 압축하는 쪽을 권한다. 기준 수치는 경험적 출발점이므로 사용자가 다른 기준을 말하면 그것을 따른다.

## 3단계: 압축 준비

압축은 대화를 요약으로 대체하므로 세부 사항이 빠질 수 있다. 두 가지로 대비한다.

### 3-1. 보존 지시문 만들기

지금까지의 대화를 훑어 새 모델이 이어서 일하는 데 꼭 필요한 것을 뽑는다.
- 현재 목표와 완료 기준
- 확정된 결정과 그 이유 (특히 사용자가 고친 것)
- 진행 중인 작업과 다음 단계
- 건드린 파일 경로, 핵심 식별자, 실패했던 시도와 원인
- 사용자의 작업 규칙·선호 중 이 세션에서 드러난 것

이를 짧은 지시문으로 만든다. Claude Code는 `/compact` 뒤에 지시문을 붙일 수 있다.

```
/compact 목표: <...>. 보존: 결정 <...>, 진행 중 <...>, 파일 <...>, 실패한 시도 <...>. 탐색 로그·중간 출력은 버려도 됨.
```

Codex의 `/compact`가 인자를 받는지는 버전에 따라 다를 수 있다. 인자를 받지 않으면 압축 직전에 위 내용을 일반 메시지로 한 번 보내 두고 `/compact`를 실행하라고 안내한다. 그러면 요약에 그 내용이 반영될 가능성이 높다.

### 3-2. 인계 메모 파일 (조건부)

사용량이 50% 이상이거나 진행 중인 작업이 여러 단계 남아 있으면, 파일 쓰기가 가능한 경우 작업 폴더에 인계 메모를 남긴다. 압축 요약이 놓친 내용을 새 모델이 다시 읽을 수 있는 안전망이다.

- 경로: `./.handoff/model-switch-YYYY-MM-DD.md` (같은 이름이 있으면 시각을 붙인다)
- 내용: 3-1의 항목을 그대로, 대화 없이도 읽히게 작성
- 비밀값(API 키, 토큰 등)은 값 대신 종류와 위치만 적는다
- 가벼운 세션이거나 파일 쓰기 권한이 없으면 생략하고, 같은 내용을 응답 안에 코드 블록으로 준다

## 4단계: 사용자에게 줄 실행 순서

아래 형식으로 한 번에 정리해서 준다. 사용자가 그대로 따라 입력할 수 있어야 한다.

```
1. (압축) <3-1에서 만든 /compact 명령>
2. (확인) <사용량 확인 명령> — 사용량이 줄었는지 확인
3. (변경) /model <새 모델명>
4. (검증) /status — 모델 이름이 바뀌었는지 확인
5. (재개) 새 모델에게 첫 메시지로 아래를 보냄
```

5번의 재개 메시지는 짧게 만든다. 예:

```
방금 모델을 <새 모델>로 바꿨다. 압축 요약(과 .handoff/<파일명>)을 기준으로 현재 목표와 다음 단계를 3줄로 정리하고, 맞으면 이어서 진행해 줘.
```

새 모델이 상태를 제대로 이해했는지 이 한 턴으로 확인할 수 있고, 틀렸으면 인계 메모로 바로잡을 수 있다.

## 주의할 점

- Codex에서 `/model` 실행 시 화면 기록이 비워지고 새 대화처럼 시작된다는 보고가 있다(공식 확인 아님). 그렇다면 압축 요약이 넘어가지 않을 수 있으므로, Codex에서는 인계 메모 파일이나 재개 메시지에 핵심 내용을 직접 담는 쪽을 더 중요하게 다룬다. 전환 후 `/status`와 재개 메시지 응답으로 맥락이 유지됐는지 확인한다.
- Claude Code의 `/model`은 선택한 모델을 이후 새 세션의 기본값으로도 저장할 수 있다. 일부 세션만 바꾸려는 경우 다른 세션의 기본값이 바뀌었는지 사용자에게 한 줄로 알려준다.
- 여러 세션을 전환할 때는 세션마다 이 절차를 따로 적용한다. 세션마다 사용량과 보존할 내용이 다르다.
- 압축이나 모델 변경이 실패하면(명령 없음, 모델 목록에 없음 등) 그 출력을 받아 원인을 보고 다음 방법을 제시한다. 모델이 목록에 없으면 CLI 업데이트(`npm i -g @openai/codex@latest`, Claude Code 업데이트) 필요 여부를 확인하게 한다.
